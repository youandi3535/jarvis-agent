# 018. 이미지 사실성 단일 초크포인트 — 검사를 늘리지 말고 출구를 줄인다

## 상태
확정 (사용자 박제 2026-08-10). ADR 010(이미지 사실성 — 차트는 JARVIS09 실데이터로만)의
**집행 방식** 을 정정·보강한다. ADR 010 의 원칙("데이터가 들어가는 이미지는 절대 거짓된
데이터로 만들면 안 됨")은 그대로 유효하며, 본 ADR 은 그 원칙이 *왜 지켜지지 않았는가* 와
*어떤 구조라야 지켜지는가* 를 확정한다. 사고 기록은 ERRORS [608] · [615].

## 배경

2026-08-10 07:00·07:31 경제 브리핑이 네이버·티스토리 양쪽에 인포그래픽 8장을 발행했다.
값 자체는 대부분 실데이터였는데도 이미지는 거짓을 말했다 —
성격이 다른 금리 8종을 더한 `합계 27.2%`, 같은 환율의 3개 시점을 더한 `합계 4,368원`,
상장유지 *요건 임계값* 을 더한 `합계 1,550억원`, 막대는 7개인데 `항목 수 8개`,
2023-08·2025-05 값을 별개 지표로 위장한 `기준금리 (2)`·`(3)`,
8행 중 1행의 날짜를 전체에 박제한 배지 `2026.08 기준`,
KOFIA·yfinance·ECOS 혼재인데 단일 표기된 출처 `한국은행 공식 경제 지표`.

적대적 반증을 통과한 확정 결함은 **21건**이었다.

**핵심 사실 — 검사기는 다 있었다.**
`verify_chart_spec`(행 수 하한 `_MIN_ROWS` 포함) · `record_provenance` ·
`verify_layout_output` 이 저장소에 실재했고 `__all__` 에도 등재돼 있었다. 그런데

1. `verify_chart_spec` 의 호출자는 `image_spec.py` 하나뿐이라 실제 렌더 경로가 지나지 않았고,
2. `verify_layout_output` 은 **나이틀리 학습 잡에서만** 호출됐고,
3. 그래서 산출물에 provenance 가 아예 없었는데(`prov=None`),
   `prepublish_gate._image_factuality_leg` 의 조건이
   `if prov and prov.get("verified") is False:` 라 **등록조차 안 된 이미지는
   "차단할 게 없다"** 로 읽혀 통과했다(fail-open).

결과적으로 8장 전부가 `{{TOKEN}}` 잔여 여부를 보는 정규식 한 줄만 통과하고 발행됐다.

여기에 두 개의 구조적 위반이 겹쳐 있었다.

- **①단일 진입점 위반** — 같은 조립 작업이 **세 벌**이었다
  (`pro_templates.build_html` 스켈레톤 / `template_engine.render_layout` /
  `infographic_engine` 내부 조립). 2026-07-06 의 "무의미한 합계 폐기" 수정은
  그중 한 벌에만 걸렸고, 2026-07-18 에 우선 경로가 바뀌면서
  **고쳐진 쪽이 도달 불가 폴백으로 강등되고 안 고쳐진 사본이 상시 실행**됐다.
- **②동적 설계의 역방향 위반** — fact 에는 행별 `as_of`·`source` 라는 진실이 있었는데
  `facts_to_datasets` 가 (category, unit) 로 묶으면서 **대표 1건만 남기고 나머지를 버렸다**.
  데이터셋 행에는 `{label, value}` 만 남았다. 검사할 대상 자체가 스키마에서 사라졌으니
  게이트를 배선해도 출처 귀속·기준일은 원리적으로 검사할 수 없었다.

## 결정

**이미지 사실성은 "검사를 늘려" 지키지 않는다. "픽셀을 낳는 출구를 하나로 줄여" 지킨다.**

다섯 가지를 확정한다.

### 1. `infographic_engine._emit` — 단일 출구
`generate_infographic` 의 반환은 정확히 **`return ""` 과
`return _ladder_emit(...)`(→ `_emit`) 두 꼴뿐**이다(실측: 함수 내 return 2개).
픽셀을 낳는 모든 경로가 `_emit` 을 지난다. 새 렌더러·새 폴백을 추가하더라도
`_emit` 을 우회하는 return 을 만들 수 없다.

### 2. `certify_image` — provenance 레지스트리의 **단독 쓰기 주체**
`_emit` 은 `certify_image` 를 호출해 검증 + provenance 등록을 받고,
**미검증이면 이미지를 폐기**한다(거짓 차트 < 차트 없음 — ADR 010 정책 유지).
레지스트리에 쓰는 코드는 `certify_image` 하나다
(실측: `_record_provenance` 의 호출부가 저장소 전체에서 `certify_image` 내부 1곳뿐). "등록됐다" 가 곧 "검증받았다" 를
의미하도록 두 행위를 분리 불가능하게 묶는다.

### 3. `prepublish_gate` — fail-closed 반전
`prov=None`(미등록)은 **통과가 아니라 차단**이다. 종전의
`if prov and prov.get("verified") is False:` 는 미등록을 무해로 읽었다.
단, 범위는 `kind` 로 좁힌다 — 수치 이미지만 fail-closed 하고
썸네일·표·재사용 이미지는 종전 계약을 유지한다(전면 차단은 4조합 즉시 발행 정지).
킬스위치 `GATE_FAIL_CLOSED=0`.

### 4. 행별 `as_of`·`source` 보존
`facts_to_datasets` 는 행에 `models.ROW_META`(`as_of`·`source`·`category`·`basis`·
`fact_id`·`verbatim`)를 실어 보내고, 데이터셋 레벨에는 대표 1건이 아니라 **분포**
(`source_mix`·`as_of_range`·`mixed_time`)를 남긴다.
표시(배지·출처 문자열)와 판정(시계열 여부·가산성)은 **모두 이 행 메타에서 파생**한다.
그 결과 배지는 `2026.08 기준` 대신 `2023.08~2026.08` 구간으로,
출처는 `금융투자협회 · 한국은행 ECOS · 한국은행` 으로 인쇄된다.

### 5. 가산성 기본값은 '불가'
`additive_total()` 은 **출처가 공표한 합계**(`ds["totals"]`)가 있을 때만 합계를 인정한다.
값이 여러 개라는 이유로 더하지 않는다. 파생 표시값(합계·항목 수·Y축 눈금·배율)은
**그리는 쪽과 검증하는 쪽이 같은 함수를 부른다**(`axis_ticks`·`outlier_pair`·`view_rows`).
차트형은 `chart_fit()` 이 행 수·형태에서 파생한다(1행 → `_kpi_cards`, 막대 아님).

## 이유

1. **게이트를 여러 출구에 각각 다는 설계는 반드시 샌다.** 이 사고가 그 증명이다 —
   2026-07-06 수정이 한쪽 조립부에만 걸렸고, 우선 경로가 바뀌자 느슨한 쪽이 출구가 됐다.
   출구가 N 개면 방어력은 *가장 느슨한 출구* 와 같다. 출구를 1개로 줄이면
   방어력과 검사기의 강도가 일치한다.
2. **"코드 존재는 적용의 증거가 아니다"(CLAUDE.md)를 구조로 강제한다.**
   `verify_chart_spec` 은 실재했고 `__all__` 에도 있었으나 라이브가 부르지 않았다.
   `grep` 으로 "있는가" 를 확인하는 검증은 이 실패 모드를 원리적으로 못 잡는다
   (동형 사고: ERRORS [614] `ensure_preflight`). 단일 출구는 "부르지 않을 수 있는"
   선택지 자체를 없앤다.
3. **진실은 데이터에 있고, 소비자는 데이터를 읽어야 한다.** 표시 산출물(라벨 문자열)을
   판정 입력으로 쓰면 *수정이 곧 새 거짓* 이 된다 — 실제로 1차 수정에서 축 라벨에
   `as_of` 를 심자 라벨 정규식 기반 `_is_timeseries` 가 뒤집혀 환율이
   `+8.6% ▲`(실제 `-8.7%`)로 인쇄됐다.
4. **fail-open 기본값은 "검사 안 함" 과 같다.** `prov=None` 통과 한 줄로 검증 체계 전체가
   무력이었다. 판정 불가는 차단이어야 하고, 부작용은 범위(`kind`)로 좁힌다.
5. **삭제가 곧 집행이다.** 사본을 남기면 다음 작업자의 손이 그리로 간다(ADR 017 이
   폐기 모델 이름을 일소한 것과 같은 논리). 이번 작업의 절반은 추가가 아니라 삭제였다 —
   총 **-5,475줄**, 3파일 물리 삭제.

## 포기한 대안

1. **게이트를 각 렌더러에 개별 배선한다** — 채택 안 함. 한쪽만 강화되면
   **느슨한 쪽이 출구가 된다.** 이 사고 자체가 그 결과이고, 렌더러가 추가될 때마다
   배선을 잊을 여지가 남는다. 방어력이 "가장 늦게 배선된 곳" 에 종속된다.
2. **라벨 문자열 파싱으로 시계열을 판정한다** — 채택 안 함. **진실이 데이터(`as_of`)에
   있는데 표시 산출물을 읽는 꼴** 이다. 실제로 `콜금리(1일)`·`통안증권 91일` 을 시간으로
   오탐하고 있었고, 라벨에 시점을 심자 판정이 뒤집혀 8개 이종 금리가 꺾은선으로 이어지고
   환율 부호가 반전됐다. 판정은 `is_timeseries(ds)` 단독으로 행 메타에서 파생한다.
3. **금지 문구 블랙리스트(`_BAD_PHRASES`)를 계속 늘린다** — 채택 안 함. ②동적 설계 위반이며,
   실측상 오염 레시피 6건 중 4건은 `source:"seed-layout"` 으로 검증기를 **거친 적이 없다**
   (JSON 직접 커밋). 어휘를 늘려도 원리적으로 안 잡힌다. **꼴**로 판정한다
   (`template_literals()`).
4. **중복 라벨을 ±5% tolerance 로 병합한다** — 채택 안 함. 1,419 vs 1,408(0.78%) 같은
   **정당한 시계열 포인트가 조용히 삭제**된다. 접미 번호 문제는 병합이 아니라
   행 메타 보존으로 푼다.
5. **`prov is None` 을 무조건 전면 차단한다** — 채택 안 함. 썸네일·표·재사용 이미지까지
   잡아 4조합 발행이 즉시 멎는다. `kind` 로 수치 이미지에 한정한다.
6. **사본을 shim 으로 남기고 새 경로만 권장한다** — 채택 안 함. shim 을 남기면
   다음 작업자의 손이 그리로 간다. `_dg_allowed`·`_dg_verify_html`·`_verify_dataset`·
   스켈레톤 조립부·`_src_label` 표를 **shim 없이 삭제**했다.
7. **합계를 "단위 화이트리스트" 로 허용한다** — 채택 안 함. 리터럴 목록은 반드시 낡고,
   같은 단위(`%`)여도 가산성이 성립하지 않는다(금리 8종). 가산성의 근거는
   **출처가 공표한 합계** 뿐이다.
